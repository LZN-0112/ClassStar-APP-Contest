# 班级档案模块改造方案

> 适用范围：`front/` 前端与 `back/` 后端（NestJS + Prisma + MySQL `class_manage_db`）
> 状态：待评审
> 目的：把「班级档案」从纯静态演示页改造成对接真实数据的可用功能

***

## 一、现状与问题

| 环节                       | 现状                                                                 | 问题                    |
| ------------------------ | ------------------------------------------------------------------ | --------------------- |
| 学期列表 `ClassArchive.tsx`  | 三个学期卡片写死，跳 `/archive-detail` 不带参数                                  | 无数据来源、跳转丢上下文          |
| 档案详情 `ArchiveDetail.tsx` | 学期名/生成人/附件全写死，无 API 请求                                             | 显示的是假数据               |
| 档案附件点击                   | `navigate('/material-detail')` 无 `fileId`                          | 详情页拿不到 id → 永远“文件不存在” |
| 导出 `ExportArchive.tsx`   | “确认导出”仅跳回列表                                                        | 无真实导出接口               |
| 后端                       | `archives`/`archive_files` 表仅在 `classes.service` 中被 `count` 用于首页统计 | 无档案查询/详情/导出接口         |

根因：档案模块未实现真实数据链路，前端是静态原型；后端表结构已存在但缺少对应接口。

***

## 二、目标

将档案链路改为「真实后端数据 + 前端动态渲染」：

1. 档案按学期真实列出（来源 `archives` 表）
2. 档案详情展示真实标题、生成人、附件（来源 `archives` + `archive_files`）
3. 附件点击进入真实文件详情/下载（衔接已有 `material` 资料库能力）
4. 导出提供真实 PDF/Excel 下载

***

## 三、数据模型（已存在，无需建表/删表）

`archives`：

- `id`、`class_id`、`title`(VARCHAR200)、`archive_year`(如 `2024-2025`)、`archive_type`、`created_by`、`status`、`created_at`、`updated_at`

`archive_files`（档案附件）：

- `id`、`archive_id`、`file_name`、`file_url`、`file_size`、`folder_name`、`uploader_id`、`download_count`、`created_at`

`materials`（资料库文件，与档案并存的另一张表，已接入真实模块）

> 说明：数据库中 `archive_files` 的 `archive_type='material'` 记录用于班级首页「资料库文件数」统计，与档案附件共用一张表。改造时**仅读取**，不做结构性变更。

***

## 四、后端改造（NestJS + Prisma）

推荐新增独立模块 `modules/archive/`（controller + service + dto + module），声明票据归属由 `class_manage_db` 现有 `classes`/`users` 关系承载。

### 4.1 接口设计（均带 JWT 鉴权 + CSRF 兼容现有拦截器）

| 方法   | 路径                                      | 说明        | 返回                                                                                         |
| ---- | --------------------------------------- | --------- | ------------------------------------------------------------------------------------------ |
| GET  | `/classes/:classId/archives`            | 按学期归档列表   | `[{id,title,archiveYear,archiveType,createdAt,creatorName,fileCount}]`                     |
| GET  | `/archives/:id`                         | 档案详情（含附件） | `{...archives, files:[{id,fileName,fileSize,fileUrl,folderName,downloadCount,createdAt}]}` |
| POST | `/classes/:classId/archives`            | 创建/归档（可选） | 新档案对象                                                                                      |
| GET  | `/archives/:id/export?format=pdf\|xlsx` | 导出档案      | 文件流（Content-Disposition 附件）                                                                |

### 4.2 关键实现要点

- **列表按学期聚合**：`prisma.archives.findMany({ where:{class_id,status:'active'} })` 后按 `archive_year` 分组；`archive_file` 计数 `_count: { select: { archive_files: true } }`。

- **详情**：`prisma.archives.findUnique({ include:{ archive_files:true } })`；`created_by` 关联 `users` 取姓名。

- **导出**：

  - XLSX：复用后端现有 `exceljs` 依赖，汇总考勤/作业/活动/班费数据（复用各现有查询）。

  - PDF：需引入 `pdfkit`（或轻量 `pdf-lib`）；若追求排版，可用 `puppeteer` 渲染 HTML 转 PDF（较重，建议二选一）。

  - `file_url` 若走 MinIO，导出时拼接/代理下载。

- **权限**：读取允许成员；创建/导出仅 `owner/admin`（复用 `currentIsAdminOrOwner` 语义对应的后端守卫或 service 内校验）。

- **参数校验**：`class-validator` DTO 校验 `classId/id/format`。

## 五、前端改造

| 文件                   | 改动                                                                                                                                                                                                               | <br />                     |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------- |

## 六、执行顺序（建议）

1. **锁定数据**：确认 `archives`/`archive_files` 中是否存在可展示的真实档案数据（无则需先造演示数据或用已有 `material` 图数据）。
2. 后端：新增 `GET /classes/:classId/archives` + `GET /archives/:id`，联调列表与详情。
3. 前端：改造 `ClassArchive` + `ArchiveDetail`，接通真实数据。
4. 后端：实现 `GET /archives/:id/export`（先 XLSX，再视需求补 PDF）。
5. 前端：改造 `ExportArchive` 触发真实导出、文件名动态化。
6. 回归：权限校验、CSRF（`POST/PUT/DELETE` 需 `X-CSRF-Token`）、空态与异常兜底。

> 建议按此拆分为多个独立小任务逐步执行，每步可单独验证，避免一次性大改。

***

## 七、注意事项（遵循项目硬约束）

- **不修改**历史数据库与已有业务数据；不删建表，仅读取现有 `archives`/`archive_files`。

- 涉及数据库的 SQL/`prisma` 变更一律先预览文本、经确认后执行。

- 前端只改动档案相关文件，**不动**班级/通知/数据/我的等无关页面。

- `archive_files` 文件 id 与 `material` id 的关系需先梳理（二者可能为两张独立表，附件详情是否可复用 `/material/:fileId` 需确认），若独立则详情展示可直接渲染 `file_name/file_size`，下载走 `archive_files` 自身逻辑或在方案评审时明确。

- 上传/OCR/权限等超出当前诉求的，不在本方案范围，可后续单列。

***

## 八、未决问题（需确认）

1. 现有数据库中 `archives` 表是否已有真实档案数据？（决定是否需要造数）
2. 档案附件在 `archive_files`（独立于 `materials`），点击后是复用 `/material/:fileId` 详情，还是需要档案附件自身的详情/下载接口？
3. 导出 PDF 采用 `pdfkit`（轻量自绘）还是 `puppeteer`（按 HTML 排版，依赖浏览器运行时）？
4. 导出内容是否需要真实汇总考勤/作业/活动/班费，还是先导出档案元数据 + 附件清单？

确认以上后即可按第六节顺序开工。
