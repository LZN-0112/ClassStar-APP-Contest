## 3. 环境适配说明（关键，扩面沿用）

| # | 问题 | 处理方式 |
| --- | --- | --- |
| 1 | Maestro CLI 直接运行受 JDK 版本与沙箱文件访问限制 | 统一用启动器 `tools/maestro/bin/maestro-sandbox.bat`：重定向 `user.home`/`LOCALAPPDATA`、classpath 前置 `patch;lib\*`（ShellFolderResolver 补丁）、`MAESTRO_CLI_NO_ANALYTICS=1`、指定 JDK17 |
| 2 | 每次运行重装 driver APK 慢且易失败 | 固定加 `--no-reinstall-driver` |
| 3 | adb server 随终端 shell 退出被回收（Windows job object） | 以常驻后台任务运行 `adb -L tcp:5037 nodaemon server`（本会话任务 id `job-d9ef811e95cc43f8acdd23e4ac2bcc12`），**该任务严禁停止** |
| 4 | MIUI 链式启动拦截：driver 发起的 `launchApp` 被系统拦截，App 不会启动 | flow 中不使用 launchApp；改为外部命令启动：`adb shell pm clear com.banwuxing.app && adb shell am start -n com.banwuxing.app/.MainActivity` |
| 5 | **★ inputText 挂死根因**：`dev.mobile.maestro` IME 未在设备已启用输入法列表中，driver 执行输入时切 IME 被拒（`Unknown input method … cannot be selected for user #0`）→ driver 挂起不返回 → gRPC 重连卡死整条 adb 通道 | 修复：`adb shell ime enable dev.mobile.maestro/.input.MaestroInputMethodService`；修复后 inputText/hideKeyboard 与收尾 logcat 收集全部恢复正常 |
| 6 | `point` 不支持小数百分比（如 `24.6%,42.2%` 会崩溃） | 坐标用绝对像素（基准 1220x2656），或整数百分比 |
| 7 | adb server 重启后 `adb reverse` 转发丢失 → 登录请求不可达（UI 全对但不跳转） | adb server 每次重启后重建 `adb -s <设备序列号> reverse tcp:3000 tcp:3000` |
| 8 | 登录成功后 MIUI 密码管理器弹「保存账号密码？」模态框，遮挡底层页面导致断言失败 | `adb shell settings put secure autofill_service null` 禁用（原值 `com.miui.passwords/.newautofill.MiuiAutofillService`） |
| 9 | 设备 offline 恢复 | adb server 重启后设备先 offline 约 30–40s 会自行变 device，勿执行 `adb reconnect offline`（会让设备从列表消失） |
| 10 | PowerShell 重定向破坏截图二进制（`adb exec-out screencap -p > x.png` 打不开） | 用 `adb shell screencap -p /sdcard/x.png` + `adb pull` |
| 11 | WebView 元素暴露特点 | 登录页输入框/协议勾选在无障碍树中无文本、无 resource-id → 坐标点击；部分卡片仅暴露 accessibilityText（如「未读通知0条」）→ 断言/点击优先选有 text 的节点或改走导航 |
| 12 | 运行结束沙箱报 `hit restricted … sessions` 且 job 标 exit 1 | 已知噪音，判定结果以 `MAESTRO_EXIT_CODE` 为准（launcher 输出行） |

## 4. 运行规范（Runbook）

先决条件：后端 `:3000` 常驻；常驻 adb server 任务在运行；设备已连接。

```
# 运行前（每次）
1. adb devices                          # 确认 <设备序列号> device；offline 等 ~30s 自恢复
2. adb -s <设备序列号> reverse tcp:3000 tcp:3000
3. adb -s <设备序列号> shell ime enable dev.mobile.maestro/.input.MaestroInputMethodService
4. adb -s <设备序列号> settings put secure autofill_service null
5. adb -s <设备序列号> logcat -c && adb -s <设备序列号> logcat -G 1M
6. adb -s <设备序列号> shell pm clear com.banwuxing.app
   adb -s <设备序列号> shell am start -n com.banwuxing.app/.MainActivity

# 运行
7. tools\maestro\bin\maestro-sandbox.bat test --no-reinstall-driver --no-ansi tools\maestro\flows\<flow>.yaml

# 判定
8. 读日志末行 MAESTRO_EXIT_CODE=0 为通过；产物在
   tools/maestro/logs/*.log 与 tools/maestro/home/.maestro/tests/<时间戳>/
   （截图、屏幕层级、commands.json 可直接用于失败取证）
```

### 6.2 新增发现与环境适配（扩面沿用）

| # | 问题/现象 | 结论与处理 |
| --- | --- | --- |
| 13 | ★ 点输入框并输入文字后弹出**全屏白色覆盖层**（WebView/MIUI 输入态，仅显示已输入文字），此时断言表单必失败 | 发送一次 BACK（`hideKeyboard`）关闭，已输入文字保留；覆盖层关闭后页面处于“上移/下滚”状态 |
| 14 | ★ 上移量随页面不同：签到表单 ~235px、注册页 ~95px、**发布通知 508px** | 同一 flow 内“首次输入前坐标”和“输入后坐标”必须分两套；一律以输入后截图/层级实测为准 |
| 15 | ★ `- back`（系统返回键）在 WebView 里会**直接退出应用回桌面** | 页面内返回必须点 BackButton（`aria-label="返回"`，`tapOn text: "返回"`）；10 flow 首轮两次实测均因此失败（取证 `step-023-assertCondition-班级动态.png` 为桌面） |
| 16 | 原生时间选择器（Chromium date/time 对话框）两个坑：入场 ~1.5s 内点击被吞；滚轮行距随渲染状态变化，固定 y 点“下一档”会落空 | `runScript: wait-picker-settle.js`（GraalJS `Date.now()` 忙等 1800ms）+ 从轮盘中心向上拖拽一行；按钮实测 清除(215,2135)/取消(793,2135)/设置(993,2132) |
| 17 | 输入框（EditText/Spinner）`text` 为空、占位符不进无障碍树，`resource-id` 不可依赖 | 表单字段只能坐标点击；断言改用**已输入值**或页面标题/按钮文案 |
| 18 | 班级首页统计卡无障碍文案是「未读通知**条**」，精确断言 `未读通知` 会失败 | 用正则 `.*未读通知.*` |
| 19 | 路由淡入转场期，**来源页文案仍在树里**：点九宫格「通知」后断标题会误匹配首页“班级动态” | 先等目标页专属文案（消息页「互动」Tab / 资料库「最近上传」等），再断业务标题；09 首轮因此误从首页进入详情，已修正复测 |
| 20 | 注册页/登录页协议勾选框为 16x16 无文本 div，坐标易点空 | 注册页勾选 (244,2030)、注册按钮蓝区中心 (611,1726)；登录页勾选 (258,2308)；均以放大截图实测 |
| 21 | 底部导航只在五个一级页渲染（首页/班级/通知/数据/我的），二级页无底栏 | 跨模块冒烟用底栏切换；个人中心无页面标题，断言「出勤率/作业完成率」；数据看板断言「数据看板/出勤趋势」 |
| 22 | `pm clear` 后立即 `am start` 偶发白屏 | preflight 改为 `pm clear → force-stop → sleep → am start` |
| 23 | 监管运行器退出码恒 0，不能据此判定 | 结果看日志 `FINAL_RESULT=SUCCESS/FAILED`；单 flow 内挂死由看门狗（stall 75s / wall 420s）取证后重试 |
