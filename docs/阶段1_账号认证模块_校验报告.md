## 四、修复记录（阶段 1 联调过程中发现并修复）

### 4.1 CSRF Cookie SameSite 策略导致 H5 跨端口请求失败

- **现象**：登录、注册等公开接口正常，但创建班级、加入班级等需 CSRF 校验的接口返回 `CSRF Token 缺失或无效`。
- **根因**：`auth.controller.ts` 中 `sessionId` Cookie 设置为 `SameSite=Strict`，在 H5 调试环境（localhost:5173 → localhost:3000）下浏览器拒绝跨端口携带该 Cookie，导致服务端无法匹配 CSRF Token 与会话。
- **修复**：将 `sameSite: 'strict'` 改为 `sameSite: 'lax'`（仅影响调试与同源跨子域场景，不影响生产 HTTPS 安全要求）。
- **文件**：[back/src/modules/auth/auth.controller.ts](file:///d:/校园班级事务智能管理助手/back/src/modules/auth/auth.controller.ts#L42-L46)

### 4.2 班级二维码数据 URL 超出数据库字段长度

- **现象**：创建班级接口返回 5000，`Invalid tx.classes.create() invocation ... too long for the column's type. Column: qr_code_url`。
- **根因**：`classes.qr_code_url` 原类型为 `VARCHAR(255)`，但后端生成的是 Base64 Data URL，长度远超 255。
- **修复**：将 Prisma Schema 与数据库表字段同步改为 `TEXT`。
- **文件**：
  - [back/prisma/schema.prisma](file:///d:/校园班级事务智能管理助手/back/prisma/schema.prisma#L183)
  - 数据库执行：`ALTER TABLE class_assistant.classes MODIFY COLUMN qr_code_url TEXT;`

### 4.3 注册页“手机号已注册”误判（排查结论）

- **现象**：使用新手机号 13800138106 注册时后端返回“手机号已注册”，但 MCP MySQL 查询未找到该记录。
- **根因**：MCP MySQL Server 连接的数据库实例与后端实际使用的数据库不一致；后端 Prisma 查询确认该手机号已存在。
- **结论**：注册接口逻辑正确，属查询工具数据源不一致导致的误判，无需代码修复。
