## 阶段 0：账号与域名准备（1 天，可并行）

1. **注册微信小程序**：微信公众平台（mp.weixin.qq.com）注册「小程序」账号。个人主体即可注册，但注意：
   - 个人主体**不能**使用「手机号快速验证组件」（getPhoneNumber），所以绑定手机号要走**短信验证码**方式（你的后端已有此逻辑可复用）。
   - 个人主体**没有** `openid` 之外的支付能力（本产品暂不需要支付，班费用记账模式，避开支付资质问题——这是正确设计）。
2. **拿到 AppID**：小程序管理后台 → 开发 → 开发设置 → AppID。
3. **服务器域名**：你的后端必须用 **HTTPS**，并在小程序后台「开发管理 → 服务器域名」配置：
   - request 合法域名：`https://你的域名`
   - uploadFile 合法域名（上传作业/资料）
   - downloadFile 合法域名（下载资料/档案）
   - 开发期可临时在微信开发者工具勾选「不校验合法域名、TLS 版本」；上线前必须配好。
4. **用户隐私保护指引**：小程序后台 → 设置 → 服务内容声明 → 用户隐私保护指引。因为用到：
   - `uni.getLocation`（定位签到）→ 声明「位置信息」
   - `uni.chooseMessageFile` / 文件上传 → 声明「相册/文件」
   - 头像昵称（如使用）→ 声明「用户信息」

## 阶段 1：配置层改造（0.5 天）

### 1.1 `mobile/src/manifest.json`
```json
"mp-weixin": {
  "appid": "wx你的小程序appid",
  "setting": {
    "urlCheck": false,
    "es6": true,
    "minified": true
  },
  "usingComponents": true,
  "permission": {
    "scope.userLocation": {
      "desc": "用于定位签到，确认你在签到范围内"
    }
  },
  "requiredPrivateInfos": ["getLocation"]
}
```
- `requiredPrivateInfos` 是基础库 2.21.3+ 的必填项，不填 `getLocation` 会被拦截。
- `urlCheck: false` 仅用于开发；发布版域名校验以公众平台配置为准。

### 1.2 `mobile/src/App.vue`（CSS 单位）
将 `100dvh` 替换为条件编译：
```css
/* 小程序/App 用 100vh，H5 保留 100dvh */
.app-root { min-height: 100vh; }
.app-mobile { min-height: 100vh; height: 100vh; }
```
（H5 的 dvh 优势是地址栏伸缩自适应，小程序无此问题，统一 100vh 即可。）

### 1.3 分包（可选，包体 > 2MB 时启用）
80+ 页面全量打进主包大概率超 2MB。在 `pages.json` 顶层加 `subPackages`，把低频页面拆出：
- 建议拆分包：`pages/material/*`、`pages/class/archive*`、`pages/class/e-archive*`、`pages/export-archive`、`pages/settings/*`、`pages/tomato`、`pages/task-board`、`pages/vote/*`、`pages/random-draw/*`
- 高频主包：`pages/home`、`pages/class/index`、`pages/notice/*`、`pages/attendance/*`、`pages/homework/*`、`pages/activity/*`、`pages/fee/index`、`pages/data/*`
- 分包跳转用 `/subPages/material/list` 前缀路径，`uni.navigateTo` 自动支持。

## 阶段 2：微信登录改造（前后端，1–1.5 天）

### 2.1 后端（`back/src/modules/auth`）

**数据库**（Prisma schema）：
```prisma
model User {
  // ...现有字段
  openid   String? @unique // 微信小程序 openid
  unionid  String?         // 可选
}
```
执行 `prisma migrate` 生成迁移。

**新增接口** `POST /auth/wechat-login`：

```ts
// 请求体
{ code: string }  // uni.login 返回的 wx code

// 流程
1. 用 code + 小程序 appid/secret 调微信接口：
   GET https://api.weixin.qq.com/sns/jscode2session
       ?appid=xxx&secret=xxx&js_code={code}&grant_type=authorization_code
2. 得到 { openid, session_key }
3. 查 users 表：
   - 命中 openid → 签发 accessToken/refreshToken，返回 { isNewUser: false, user }
   - 未命中 → 创建"未绑定手机号"的占位用户（或返回 isNewUser: true 让前端先走绑定）
4. 返回 { accessToken, refreshToken, user, isNewUser }
```

**注意**：
- appid/secret 放 `back/.env`，**禁止**写死源码（你的 `.env.example` 有惯例）。
- code2session 是服务端调用，**绝不能在前端调**（secret 会泄露）。
- 占位用户登录后若 `isNewUser`，前端引导到「绑定手机号」页，复用现有 `/auth/register` 或新增 `/auth/bind-phone`（手机号+短信验证码 + openid 关联）。

### 2.2 前端（`mobile/src/pages/auth/login.vue`）

把占位函数 `wechatLogin()` 换成真实实现：

```ts
async function wechatLogin() {
  if (loading.value) return
  loading.value = true
  try {
    // #ifdef MP-WEIXIN
    const { code } = await new Promise<any>((resolve, reject) => {
      uni.login({ provider: 'weixin', success: resolve, fail: reject })
    })
    const res = await wechatLoginByCode(code) // 调 /auth/wechat-login
    setTokens(res.accessToken, res.refreshToken)
    secureStorage.set('userInfo', res.user)
    if (res.isNewUser) {
      uni.redirectTo({ url: '/pages/auth/bind-phone' }) // 新增绑定页
    } else {
      uni.redirectTo({ url: '/pages/home/index' })
    }
    // #endif
    // #ifndef MP-WEIXIN
    uni.showToast({ title: '请在微信小程序中使用微信登录', icon: 'none' })
    // #endif
  } catch (err) {
    uni.showToast({ title: err instanceof Error ? err.message : '微信登录失败', icon: 'none' })
  } finally {
    loading.value = false
  }
}
```

**`common/api/auth.ts` 新增**：
```ts
export function wechatLoginByCode(code: string) {
  return request.post<LoginResult & { isNewUser: boolean }>(
    '/auth/wechat-login', { code }, { needAuth: false, needCsrf: false })
}
```

### 2.3 新增「绑定手机号」页（`pages/auth/bind-phone.vue`）
- 手机号 + 短信验证码（复用现有验证码逻辑）+ 学号（可选）
- 提交后调 `/auth/bind-phone`（后端把 openid 关联到已有手机号用户，或为新用户补全信息）

## 阶段 3：图标方案替换（最大改造点，1–2 天）

### 问题
`AppIcon.vue` 用 `@iconify/vue` 的 `<Icon>`，它内部是 Web 组件 + DOM 渲染，微信小程序无 DOM，**全项目图标都会失效**。所有页面和 TabBar 都依赖它。

### 推荐方案：条件编译双实现
1. **H5 / App 端保持现状**（iconify 渲染效果最好）。
2. **小程序端改为 `<image>` 渲染预置图标**：

```vue
<template>
  <!-- #ifdef H5 || APP-PLUS -->
  <Icon :icon="icon" :width="toSize(size)" :height="toSize(size)" :color="color" class="app-icon" />
  <!-- #endif -->
  <!-- #ifndef H5 || APP-PLUS -->
  <image
    class="app-icon-img"
    :src="iconSrc"
    :style="{ width: toSize(size), height: toSize(size) }"
  />
  <!-- #endif -->
</template>
```

3. **生成图标资源**：统计代码里实际用到的 icon 名（如 `lucide:home`、`mdi:wechat`、`tabler:chart-pie`），去 iconify 官网（iconify.design）或 `https://api.iconify.design/{前缀}/{名字}.svg` 批量下载 SVG，用脚本统一转成 PNG 或直接放 SVG 到 `src/static/icons/`，命名映射：`lucide-home.png`。小程序 `<image>` 支持 SVG（基础库 2.3.0+，但 PNG 更稳，推荐 PNG）。
4. `iconSrc` 映射函数：`{ 'lucide:home': '/static/icons/lucide-home.png', ... }`。
5. 替换后跑 `npm run dev:mp-weixin`，逐个页面核对图标。

**备选方案**：全部换成 `uni-icons`（`@dcloudio/uni-ui`），但内置图标集有限，需要把 6 套 iconify 图标重新映射，改动面更大，不推荐。
