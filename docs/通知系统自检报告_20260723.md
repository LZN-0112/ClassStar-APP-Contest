## 6. 问题定位与说明

### 6.1 发现的现象

在浏览器自动化测试过程中，观察到以下现象：

1. **点击列表项后页面视觉上未切换**：点击通知项后，`window.location.href` 已正确变为 `/message-detail/{id}`，但 DOM 中仍保留旧页面（通知列表页），新页面未在视觉上呈现。
2. **直接访问详情页 URL 后页面不可见**：直接导航到详情页 URL 时，DOM 中详情页内容已正确加载，但根容器 `opacity` 为 `0`，视觉上不可见。

### 6.2 原因分析

通过浏览器诊断发现：

- `document.hidden === true`
- `document.visibilityState === 'hidden'`

浏览器自动化工具在后台以隐藏标签页运行。当页面处于隐藏状态时，浏览器会暂停 `requestAnimationFrame` 和 CSS 动画以节省资源。项目使用 `framer-motion` 实现页面转场动画（`PageTransition.tsx`），其动画依赖 `requestAnimationFrame`。因此：

- **点击跳转时**：旧页面的 exit 动画被暂停，`AnimatePresence mode="wait"` 等待 exit 完成后再挂载新页面，导致新页面无法渲染。
- **直接导航时**：新页面的 enter 动画被暂停在 `initial={{ opacity: 0, x: 20 }}` 状态，导致页面内容加载但不可见。

**结论**：此现象是浏览器自动化测试环境（隐藏标签页）的限制，并非通知系统代码缺陷。代码逻辑（路由、API 调用、状态更新）均正常。

### 6.3 验证与绕过

为在自动化环境中完成测试，通过 `browser_evaluate` 执行以下临时操作：

1. 直接导航到详情页 URL，验证详情页内容已正确加载。
2. 手动将根容器 `style.opacity` 设置为 `1`、`style.transform` 设置为 `none`，使详情页可见。
3. 点击“确认签收”按钮，验证签收状态正确更新。

上述操作仅用于绕过自动化环境的动画暂停限制，未修改任何业务源代码。

### 6.4 真实浏览器预期行为

在真实用户浏览器中：

- 页面默认处于 `visible` 状态。
- `framer-motion` 动画会正常执行。
- 点击通知列表项后，页面会平滑切换到详情页并完整显示内容。
- 不存在“页面不存在”或详情页无法显示的问题。
